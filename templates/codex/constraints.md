# Constraints · 边界与红线

> 示例模板。按项目实际情况修改；Edward 只读遵守。

## 不可触碰

- 不删除或覆盖人类维护的 `edward/codex/`、`edward/knowledge/references/`。
- 不把密钥、令牌、个人数据写进报告、日志或知识库。
- 不执行超出项目范围的破坏性命令。
- 未经人类在 `report-reply` 明确批准，不改变项目目标。

## 质量门禁

- 代码变更必须通过项目已有测试；没有测试时，至少给出可复现的验证命令。
- 部署前必须有回滚方案。
- 对外发布、付费、删除数据等高风险动作必须等待人类批准。

## 汇报要求

- 每个班次必须生成 `reports/<run-id>.md`。
- 阻塞项和待决策项必须写清楚，不能只在对话里提。
- 收工前必须声明下一次唤醒时间。

## 审批规则

| 动作 | 是否需要人类批准 | 批准位置 |
|---|---|---|
| 修改目标 | 是 | `report-reply` |
| 生产部署 | 是 | `report-reply` |
| 删除数据 | 是 | `report-reply` |
| 日常开发 / 测试 | 否 | 记录在 report |
